## Поля и контейнеры

Обычная охранная зона от видимого габарита до текста/других знаков: **131 u**, одна боковая толщина ленты. Встроенные 60 u не заменяют охранную зону; добавляйте недостающие поля средствами layout.

Аватар занимает **78% ширины квадратного canvas**. Боковые поля по 11% соответствуют примерно 135.67 u исходной геометрии. Высота знака получается автоматически: около 39.65% canvas. Положение центрировано, никакого stretch X/Y нет.

Радиус rounded-square — **18% стороны**, примерно 1.69 боковой толщины ленты в этом масштабе. Он смягчает контейнер, сохраняя отличие от круга. Проверено, что круг и rounded-square не срезают ни одного пикселя знака относительно квадратного варианта.

Maskable PWA: ширина знака 70% canvas. Даже углы его габаритного прямоугольника находятся внутри гарантированной центральной зоны r=40%. Apple touch icon — непрозрачный квадрат; углы оформляет ОС.

## Малые размеры и micro

Проверен master на ширинах **16, 20, 24, 32, 40, 48, 64, 96, 128, 180, 256, 512, 1024, 2048 px**. Это ширина всего SVG canvas, не квадратного аватара. Минимальный геометрический просвет 5.336 u превращается в 0.079 px при ширине 16 px и 0.473 px при 96 px.

На DPR 1 пороговый тест исходного master объединяет ленты при 16–96 px. На 128 px две основные области разделены. Это признак потери тонких зазоров, а не поломка контура; характер знака остаётся различим. Для уверенного отображения тонкого узла предпочитайте master от **128 физических пикселей ширины**. Нельзя превращать этот конкретный пороговый тест в универсальный предел человеческой читаемости.

Для компактных случаев **24–64 px** создана отдельная optical-size версия:

- `svg/logo-micro.svg` — silver, прозрачная;
- `svg/logo-micro-white.svg` — white, прозрачная;
- favicon suite использует white micro на charcoal badge.

Micro сохраняет исходные path дословно. Три локальных векторных knockout-канала шириной **28 u** расширяют существующие отрицательные пространства центра, немного упрощая окончания складок. Для favicon badge применена отдельная настройка **40 u**, проверенная на 16/32/48 px. Локальная luminance mask нужна для прозрачности и сохранения исходных кривых в производном файле; растровых масок и filters нет. Контейнеры и обычные цветовые варианты этой коррекции не используют.

Одна усиленная настройка для всех размеров оказалась хуже: 40 u разделяли знак на 16 px, но в прозрачном SVG на 20 px могли отделять маленький фрагмент окончания. Поэтому для обычного micro оставлены 28 u, а усиление ограничено favicon-контейнером и его проверенными размерами. Сравнение кандидатов сохранено в `tests/micro-width-selection.json`.

В прозрачном micro SVG на 16–20 CSS px тонкие зазоры всё ещё могут сливаться в некоторых движках. Для этих размеров используйте готовую favicon-композицию/PNG; полный разворот прозрачного micro уверенно проверен от 24 px. Эта ограниченная читаемость явно отражена в [browser-micro-summary.json](tests/browser-micro-summary.json), не объявлена успешным тестом всех размеров.

На 16/20/24/32 px micro сохраняет две основные области в том же alpha-тесте. Сравнение и точные координаты каналов: [asset-qa.json](tests/asset-qa.json), [asset-manifest.json](tests/asset-manifest.json). В preview есть нативный размер и увеличение по пикселям. На отдельных размерах возможны очень маленькие антиалиасные фрагменты у острых концов; тест основных областей исключает ≤2 px и ≤1% площади. Глобальная геометрия master не менялась.

Не заменяйте master micro-версией в больших макетах. При inline-вставке нескольких micro SVG задавайте уникальные ID масок и соответствующие локальные ссылки; через `<img>` документы изолированы и конфликта ID нет.

## Цвет и видимость

Digital source of truth — sRGB. [brand-colors.json](brand-colors.json) содержит HEX/RGB/HSL, [brand-tokens.css](brand-tokens.css) — CSS variables.

| Цвет | HEX | Назначение |
| --- | --- | --- |
| Silver | `#c4c4c4` | Основной знак; сохранён цвет утверждённого master |
| Charcoal | `#1d1c1b` | Основной фон; близок медиане фона референса |
| White | `#ffffff` | Контрастная тёмная тема, monochrome |
| Black | `#000000` | Монохром на светлом фоне |

Silver/charcoal: **9.756:1**. White/charcoal и charcoal/white: **17.015:1**. Black/white: **21:1**. Silver/white: **1.744:1 — avoid**. Рекомендации preferred ≥7:1 и acceptable ≥3:1 являются внутренней проверкой видимости, не обязательным WCAG-критерием для логотипов.

Проверены светлые, тёмные, серые и почти чёрные контексты в preview. Отдельные калиброванные OLED/IPS не использовались. CMYK не назначен: для печатного производства нужен профиль конкретного процесса. `tests/vector-proof.pdf` подтверждает векторное размещение в RGB PDF, а не цветопробу печати.

## HTML и доступность

Для смыслового изображения достаточно описательного alt:

```html
<a href="/" aria-label="Maxim Zolotoy — главная">
  <img src="/brand/svg/logo-charcoal.svg"
       alt="" aria-hidden="true" style="width:160px;height:auto">
</a>

<img src="/brand/svg/logo-silver.svg"
     alt="Логотип Maxim Zolotoy" style="width:200px;height:auto">
```

В первом примере смысл несёт ссылка, поэтому картинка декоративная. Во втором изображение самостоятельное. Для inline SVG можно использовать `role="img"`, `aria-labelledby="unique-logo-title"` и `<title id="unique-logo-title">Логотип Maxim Zolotoy</title>`, сохраняя сами path без изменений. Не добавляйте повторяющийся обязательный title в переиспользуемые asset-файлы.

## Подключение favicon и social

Пример предполагает, что папка размещена по публичному пути `/brand/`. Это пример интеграции, а не уже выполненный деплой.

```html
<link rel="icon" href="/brand/favicon/favicon.ico" sizes="16x16 32x32 48x48">
<link rel="icon" href="/brand/favicon/favicon.svg" type="image/svg+xml" sizes="any">
<link rel="apple-touch-icon" href="/brand/favicon/apple-touch-icon.png" sizes="180x180">
<link rel="manifest" href="/brand/favicon/site.webmanifest">
<meta name="theme-color" content="#1d1c1b">

<meta property="og:image" content="https://example.com/brand/social/opengraph-1200x630.png">
<meta property="og:image:type" content="image/png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:image:alt" content="Логотип Maxim Zolotoy на графитовом фоне">
```

Замените example.com реальным публичным доменом и проверьте URL после интеграции. `site.webmanifest` содержит `id` и `start_url` `/`; адаптируйте их к приложению. Иконки сами по себе не гарантируют PWA installability. ICO содержит PNG-кадры 16/32/48 без повторного ресайза. Apple icon 180; PWA any и maskable 192/512.

SVG favicon проверен как отображаемый ресурс в Chromium/Firefox/WebKit и показан на светлой/тёмной рамке. Поведение нативных закреплённых вкладок, закладок и установки на устройство отдельно не подтверждено. Непрозрачный charcoal badge предотвращает исчезновение белого знака на светлом фоне.

OpenGraph 1200×630 — рабочий формат комплекта, не обязательный размер самого протокола. Знак шириной 480 px остаётся целиком внутри центрального квадратного crop; ширина не растягивается. При загрузке на сервис возможны его собственные преобразования.

## Сборка и проверка

Из папки `brand`:

```sh
npm ci
npm run build
npm run qa
python3 scripts/qa-svg.py
python3 scripts/build-review.py
python3 scripts/serve-preview.py --port 8765 --reference '/path/to/мое лого.png'
```

В другом терминале:

```sh
npx playwright install chromium firefox webkit
npm run test:browsers
```

`LOGO_PREVIEW_URL` позволяет задать иной localhost URL. При использовании уже установленного Chromium можно передать `LOGO_CHROMIUM_PATH`. Для окружения с общими пакетами сборщик поддерживает `LOGO_NODE_MODULES`; обычному `npm ci` это не требуется.

Исторический анализ геометрии требует Pillow/numpy/scipy/shapely/svgpathtools и оригинальный PNG. `geometry/analyze_geometry.py /path/to/reference.png` выполняет только чтение мастера и расчёты. Не запускайте старый построитель для изменения утверждённого знака.

## Что запрещено

Не менять Bézier-кривые master, пропорции, толщину, внутренние пространства, twist, пересечения и внешний силуэт. Не растягивать X/Y независимо, не вращать произвольно, не добавлять обводки, тени, gradients или псевдообъём. Не обрезать петли и не уменьшать поля без проверки конкретного носителя. Использовать утверждённую палитру и контрастный вариант для фона.

Единственное описанное геометрическое исключение — отдельная micro-маска для малого размера. Если дальнейшая проблема требует правки самого master, остановить работу и согласовать изменение с владельцем.

Файлы подготовлены локально. Сайты и аккаунты не изменялись; platform tests моделируют crop и размер, а не подтверждают приём файлов реальными сервисами. Остальные ограничения и фактически пройденные проверки перечислены в [final-qa.md](tests/final-qa.md).
